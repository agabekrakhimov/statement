# Fleet Settlement Dashboard (prototype)

Turns weekly "Truck Owner Settlement" / "Driver Pay Settlement" PDFs (the
kind generated by datatruck.io-style dispatch platforms) into a running
fleet analytics dashboard: RPM (revenue/mile), CPM (cost/mile), true
profit per mile *after fuel*, deduction breakdowns, maintenance spend,
deadhead %, fuel $/mile and MPG, a driver-pay and compliance log, and
automatically generated "what needs attention" insights — per truck, per
week.

**Why "true profit" and not just the carrier's net pay**: these carrier
statements almost never have fuel deducted from "net pay" — it's a
separate card balance or paid out of pocket. So the carrier's number
overstates what a truck actually made. The dashboard computes
`net pay − fuel cost` as **True Profit** and ranks/sorts trucks by that,
not the carrier figure, while still showing the carrier number alongside
it for reference.

Every number in the app is editable, not just whatever a PDF happened to
contain: click **Edit** on any week to fix or fill in anything (fuel cost
and gallons included — fuel is rarely on these statements, so you're
expected to type it in from a fuel card/receipt), **+ Add week manually**
to enter a week with no PDF at all, and **Export/Import backup** to get
your data out of browser storage as a JSON file.

Built from — and validated against — 5 real weekly statements for a
one-truck owner-operator. See `PROMPT.md` for the full product spec this
prototype implements a slice of, and for what's still missing to get real
fuel-economy numbers and a true owner P&L.

## Run it

No build step, no server required — it's a static page.

```
cd statement
python3 -m http.server 8080
# then open http://localhost:8080
```

(Opening `index.html` directly with `file://` also works in most browsers,
but a local server avoids any browser restrictions on `fetch`/module
loading, so it's the more reliable option.)

On first load it seeds itself with the 5 sample statements so the
dashboard isn't empty. Use **Reset to sample data** to get back to that
baseline, or **Clear all** to start fresh with your own uploads.

## How it works

- `js/pdf-lines.js` — extracts text from an uploaded PDF using pdf.js,
  reconstructing visual table rows by clustering text by Y-position (these
  statements are visually tabular, not tagged tables, so a naive
  reading-order text dump would scramble columns).
- `js/parser.js` — a regex-based parser tuned to the Wenze Transport
  Services / datatruck.io statement layout. It never fails silently: every
  parsed statement goes through the same edit form you'd use to fix a
  week by hand, pre-filled with whatever it found, before it's saved.
- `js/metrics.js` — pure functions turning flat per-week records into
  metrics (RPM, CPM, net RPM, deadhead %, cost/mile by category, real or
  estimated MPG and fuel $/mile), per-truck rollups, and a rule-based
  insights engine (maintenance spikes, high deadhead, declining trends,
  duplicate/conflicting statements, missing fuel data, fines).
- `js/charts.js` — Chart.js rendering: RPM/CPM/net-RPM trend, a CPM-vs-RPM
  stacked-cost-vs-revenue chart, deduction breakdown, fuel $/mile & MPG,
  maintenance-vs-trailing-average, and deadhead %.
- `js/store.js` — localStorage persistence plus edit/delete/export/import,
  keyed by a stable `recordId` per week (independent of the carrier's own
  statement ID, which can collide or get re-issued). Swap this module out
  for a real backend to go to production — see `PROMPT.md`.
- `js/app.js` — glues it together: tabs, upload flow, the unified
  edit/add/review modal, rendering.
- `vendor/` — Chart.js and pdf.js, vendored locally so the app works fully
  offline with no CDN dependency.

## Uploading your own statements — or skipping PDFs entirely

Click **+ Upload statement(s)**, drop one or more PDFs. Statements from
the same carrier/template as the 5 samples should parse with zero manual
entry; anything else will show the edit form with whatever it can piece
together and clearly flag missing fields — it never just drops a file it
couldn't fully parse.

If you don't have a PDF, or the statement has data the PDF doesn't
(fuel, for instance), you don't need one: **+ Add week manually** opens
the same form blank, and **Edit** on any existing week reopens it
pre-filled so you can correct or add to it — including fuel, which these
carrier statements essentially never include.

## Fixing a week / adding fuel data

Every week in the **Weekly Data** tab has **Edit**, **Duplicate**, and
**Delete**. Fuel cost and gallons live in their own section of the edit
form — enter cost alone and MPG is estimated from the diesel price in the
toolbar; enter gallons too (from a receipt or fuel card export) and MPG
becomes exact. The insights panel tells you which weeks are still missing
fuel data, and flags any week whose numbers don't add up (gross − driver
pay − deductions ≠ net pay), which usually means a typo.

**Duplicate** starts next week's entry from the current one: it carries
over the truck, driver, and the deduction categories that tend to repeat
(insurance, trailer, ELD, IFTA, company fee) with next week's date range
already filled in, but blanks out everything specific to that week's
trip — miles, revenue, net pay, fuel, maintenance — so it's never
mistaken for real data until you fill those in.

## Fixed costs & breakeven

The **Truck Comparison** tab has a **Fixed Costs & Breakeven** section —
none of this is on a carrier statement (truck payment/lease, physical
damage insurance, permits, ELD hardware, parking/tolls), but it's real
cost that has to be covered before a truck is actually profitable.
Enter it once per truck, as a monthly figure; the app converts it to a
weekly and per-mile cost using that truck's own average weekly mileage
and computes a **breakeven RPM** — the revenue/mile the truck needs just
to cover deductions, fuel, and fixed costs. If a truck's actual RPM falls
below that, it shows up as a critical insight, not just a quiet number in
a table.

## Notes

Every week's edit form has a free-text **Notes** field for anything worth
remembering that doesn't fit a number — a bad lane, a broker to avoid, why
a load was mostly deadhead. It shows as a 📝 preview (full text on hover)
in the Weekly Data table.

## Known limitations (this prototype)

- One statement template is auto-parsed out of the box (Wenze Transport
  Services / datatruck.io). Other carriers' PDFs will need either a new
  parser module or just entering the week by hand — same form either way.
- Fuel is essentially never on these carrier statements, so it starts
  blank for every week until you enter it yourself.
- Data lives in this browser's localStorage only — clearing site data or
  switching browsers/devices loses it. Use **Export backup** regularly
  and **Import backup** to restore/merge; a real deployment needs a
  backend (covered in `PROMPT.md`).
